The engine

Seven systems, each built and each verified

The factory no longer jumps from prompt straight to a recipe. It infers requirements, plans a topology, justifies the choice, researches its own gaps, generates, then audits both the sound and the code — the reasoning spine a senior engineer brings before writing a line.

Built
Requirements engineer

Reads the brief, not just the noun

"Make a compressor" isn't a spec. It infers source material, character, and latency budget from the wording — and records the evidence for each call, so a live vocal never gets a lookahead design.
verified requirements.ts · topologyTest
Built
Engineering planner

Chooses a topology, and says why

12 gate-verified designs compete: peak vs. RMS detection, feed-forward vs. feedback, soft-knee, lookahead, tube vs. fuzz. The winner ships with a plain-English rationale tied to the words you used.
verified dspTopologies.ts · topologyTest
Built
Knowledge graph

Concepts and edges, not keywords

Every module carries concept tags and links — compressor → detector → attack/release → lookahead. The planner traverses the graph to route requirements; the auditor measures coverage against it.
verified knowledgeGraph.ts · knowledgeAuditTest
Built
Knowledge auditor

Grades itself like a curriculum

Coverage per area, an honest gap report (the shopping list), trust tiers, and 18 benchmarks really built and gated at audit time. Run npm run audit for the dashboard.
verified knowledgeAudit.ts · knowledgeAuditTest
Built
Research engine

Fills gaps — behind your approval

Plan → gather (cited corpus + local model + opt-in live web + the OpenAudio index) → detect conflicts → gate-verify a proposed module → wait for you. Nothing becomes knowledge until you approve it.
verified researchEngine.ts · 3 suites
Built
Code generator + quality gate

Best-of-N, floored at 97

Deterministic candidates measured on real program material: gain, DC, dead knobs, aliasing, true-peak, stereo width, and per-knob honesty. Only ships when every dimension clears 97/100.
verified qualityGate.ts · 8 suites
Built
Self-review · two auditors

Grades the code, not just the sound

A JS auditor scores real-time safety, numerical robustness, smoothing and maintainability; a C++ auditor scans the exported JUCE for heap, locks, IO, and denormal hazards before it compiles. It caught a real bug in our own sampler.
verified codeAudit + cppAudit · 2 suites

Honest ledger

What's genuinely left

Not a wishlist — the specific, bounded work that remains. Two are additive; one is a single structural change that unlocks the last blocked concept.

Structural · unlocks 1

A second input bus

The DSP contract carries one input (plus the stereo pair). A second keyed bus would un-block external sidechain — the only remaining honestly-blocked concept.

Additive

Deeper native C++ metrics

The C++ auditor covers real-time safety today. Cyclomatic complexity, allocation graphs, and static-analysis passes on the exported project are the next layer.

Ongoing · demand-driven

Catalog breadth

Coverage grows from the gap report and logged unserved prompts — each new module cited and gate-verified, not added by quota. The method is built; the library keeps filling.
