---
name: Audio project brief truth
description: Durable rules for keeping collaborative audio briefs, previews, revisions, and evidence aligned.
---

An audio project brief is an executable product contract, not display-only metadata. Structural decisions must update the corresponding model, graph, controls, or runtime, and persisted previews must hydrate from that same project.

**Why:** A convincing project card can otherwise claim an audition or workstation preview while opening an unrelated runtime, and category changes can misleadingly carry old proof into a new design.

**How to apply:** Keep one shared project identity through revisions. Preserve prior-category checks only as conceptual provenance, independently validate the new category, and reconcile later brief changes without silently deleting saved user work.
